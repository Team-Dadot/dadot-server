# 면접 공시 근거의 쉬운 해석

`GET /v1/interview-questions/{questionId}`의 `data.evidence[]`에 nullable 문자열 `interpretation`을 추가한다.

```json
{
  "quote": "회사는 해외 판매망을 확대할 계획입니다. 현지 유통사를 추가할 예정입니다.",
  "interpretation": "이 회사는 해외 판매망을 넓힐 계획이에요. 현지 유통사를 추가하려는 내용이에요."
}
```

위는 가상 예시다. 원문은 `quote`에 그대로 보존하며, `interpretation`은 그 근거의 인용문만 쉬운 말로 설명한다. 원문에 없는 전망·인과관계·기업 사실·예시 답변을 추가하지 않도록 생성 지침을 적용한다. 근거별로 권장 2문장, 정보가 짧으면 1문장을 허용하고 최대 180 Unicode 코드 포인트다. 마침표로 끝나는 완결된 설명문 1~2개인지 서버에서 검사한다. 프롬프트를 통한 사실 일치 지침과 출처 ID·원문 인용 일치 검사는 의미상 사실 일치를 완전히 증명하는 검사가 아니다.

V22는 `interview_question_evidence.interpretation TEXT NULL`을 추가한다. 새로 생성한 해석을 인용문과 같은 근거 행에 저장해 조회 때 재생성하지 않는다. 기존 질문의 값은 null로 유지하며 보정·재생성하지 않는다. `quote`, 보고서 제목·링크·날짜·기간·정정 상태는 기존 필드를 유지한다.

확인한 앱 `fc01dcc`는 `interpretation`을 읽어 원문 아래에 `해석 · ...`로 표시하는 코드가 있다. 이 서버 패키지는 앱 코드를 변경하지 않는다. 원문을 접거나 요약을 위에 배치하는 UI는 구현하지 않는다. 근거가 여러 개면 각 근거마다 별도 해석이 표시되므로 카드 전체가 정확히 2문장이 되는 구조는 아니다.

새 AI 응답에는 각 근거의 해석이 필수다. 기존 질문·기존 저장 객체에 해석이 없는 경우의 호환 경로는 유지한다. 새 해석의 누락·길이·문장 형식 실패는 기존 생성 작업의 최대 3회 시도 안에서 다시 생성하며, 출처 불일치나 과금 한도 등의 기존 실패 정책은 유지한다.

질문 길이·종결형 정책과 평가·피드백·퀴즈 생성은 변경하지 않는다. 생성 정책 해시는 바뀌므로 진행 중인 면접 생성 작업을 완료한 후 배포한다.
